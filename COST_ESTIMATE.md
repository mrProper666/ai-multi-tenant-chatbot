## Как се “таксува” AI в този проект

Проектът използва **Vercel AI Gateway** (routing/observability) + избрани модели `provider/model` (например `openai/gpt-4o-mini`, `anthropic/claude-sonnet-4.5`, `google/gemini-embedding-001`).

### Какво плащаш
- **Няма абонамент за AI SDK** (библиотека).
- Плащаш **токени** (LLM) и **embedding input tokens** (embeddings), по цените на провайдъра (AI Gateway е без markup).

### 2 основни “двигателя” на AI разхода
- **Chat**: \(input tokens\) + \(output tokens\) на разговор
- **Embeddings**: \(input tokens\) при качване/обработка на документи (обикновено по-рядко от chat)

## “Точно” остойностяване за 1 НПО (дадени параметри)

### Входни параметри
- **Тенант(и)**: 1 НПО
- **Документи/месец**: 10–15 PDF
- **Средно страници/документ**: 20
- **Въпроси/ден**: 40–50

### Изчисления (обеми)
- **PDF страници/месец**: \(10–15\) × 20 = **200–300 страници**
- **Въпроси/месец** (30 дни): \(40–50\) × 30 = **1,200–1,500 въпроса**

### Допускания (за да се превърне в $)
Тук “точността” зависи от token-и. За RAG чатбот като този реалистичните средни са:
- **Среден input на въпрос**: **4,000 tokens**  
  (system prompt + история + “Context from documents” с няколко chunks)
- **Среден output на въпрос**: **600 tokens**
- **Текст за embeddings**: **~700 tokens/страница** средно, и ~1.23× overhead от overlap (800/650)  
  ⇒ embeddings input tokens/месец ≈ pages × 700 × 1.23

> Ако вашите PDF-и са много “плътни” или retrieval връща дълги chunks, input tokens може да е 6k–10k. Ще дам число и за това като worst‑case.

## Променлив разход: AI (chat + embeddings)

### Chat (LLM)

#### Вариант A (препоръчан за “евтин”): `openai/gpt-4o-mini`
Цени (ориентир): input **$0.15/1M**, output **$0.60/1M** токена.

- **Цена/въпрос**:
  - input: 4,000 × \(0.15 / 1,000,000\) = **$0.00060**
  - output: 600 × \(0.60 / 1,000,000\) = **$0.00036**
  - общо: **$0.00096/въпрос**
- **Цена/месец** (1,200–1,500 въпроса): **$1.15 – $1.44**

**Worst‑case** (10,000 input + 1,000 output tokens):
- цена/въпрос ≈ 10,000×0.15/1M + 1,000×0.60/1M = **$0.00210**
- цена/месец ≈ **$2.52 – $3.15**

#### Вариант B (по-скъп LLM): `openai/gpt-4o`
Цени (ориентир): input **$2.50/1M**, output **$10.00/1M** токена.

- **Цена/въпрос**:
  - input: 4,000 × \(2.50 / 1,000,000\) = **$0.01000**
  - output: 600 × \(10.00 / 1,000,000\) = **$0.00600**
  - общо: **$0.01600/въпрос**
- **Цена/месец** (1,200–1,500 въпроса): **$19.20 – $24.00**

### Embeddings (качване на документи)

#### Обем embeddings tokens/месец (при допусканията)
- pages: 200–300
- tokens: 200–300 × 700 × 1.23 = **172,200 – 258,300 tokens**

#### Вариант A: `openai/text-embedding-3-large` (3072d)
Цени (ориентир): **$0.13 / 1M input tokens**.

- месечно: 172,200–258,300 × \(0.13 / 1,000,000\) = **$0.02 – $0.03**

#### Вариант B: `google/gemini-embedding-001` (3072d)
Цени (ориентир): **$0.15 / 1M input tokens**.

- месечно: 172,200–258,300 × \(0.15 / 1,000,000\) = **$0.03 – $0.04**

## Сценарий 1 — Евтин (MVP / нисък трафик)

**Цел**: минимална месечна поддръжка за пилот (1–2 НПО), нисък риск, базов SLA.

### Препоръчана конфигурация
- **Vercel**: Pro (1 developer seat) — **$20/месец**
- **DB**: Neon Free — **$0/месец** (или Neon Launch при нужда)
- **Storage**: Cloudflare R2 — **$0–$2/месец** (в зависимост от GB)
- **AI Gateway**: $0 фиксирано + **usage**

### Ориентировъчен total (месец)
- **Фиксирано**: ~**$20–$25**
- **Променливо (AI usage)**: типично **$5–$30**
- **Общо**: **~$30–$50/месец**

### Примерна AI сметка (илюстративно)
- 10,000 въпроса/месец
- LLM: „евтин“ модел (напр. `gpt-4o-mini`)
- Средно на въпрос: ~3k input tokens + ~600 output tokens
- Ориентировъчно: **~$8–$15/месец** за chat (embeddings обикновено < $1–$5 при малък ingest)

## Сценарий 2 — Скъп (Production / висок трафик + повече гаранции)

**Цел**: по-висока надеждност, повече потребители/НПО, по-мощна DB, по-скъпи модели и повече трафик.

### Препоръчана конфигурация (пример)
- **Vercel**: Pro с ~5 developer seats — **~$100/месец** (+ usage)
- **DB (вариант A)**: Supabase Team — **$599/месец**
  - (или **DB (вариант B)**: Neon Launch/Scale usage‑based — типично **$150–$700+/месец** при постоянно натоварване)
- **Storage**:
  - Cloudflare R2 (пример 500 GB): **~$7.50/месец** (egress free)
  - (или Vercel Blob / AWS S3 при нужда, но egress/transfer може да качи разхода)
- **AI Gateway**: $0 фиксирано + **usage** (доминираща част)

### Ориентировъчен total (месец)
- **Фиксирано (без AI)**: ~**$700–$900/месец** (в зависимост от DB/екип)
- **Променливо (AI usage)**: **~$1,000–$3,000+/месец** при висок трафик
- **Общо**: **~$1,500–$3,000+/месец**

### Примерна AI сметка (илюстративно)
- 100,000 въпроса/месец
- LLM: по-скъп модел (напр. `gpt-4o` клас)
- Средно на въпрос: ~3k input tokens + ~600–1000 output tokens
- Ориентировъчно: **~$1,300–$2,000+/месец** само за chat

## Кога кой вариант има смисъл

### Евтин
- пилот/PoC
- малко НПО и малко потребители
- приемаш по-малко гаранции за latency/SLA

### Скъп
- production за повече НПО/потребители
- по-висока достъпност/поддръжка/контрол (DB + ops)
- по-голям трафик и/или по-качествени/скъпи модели

---

## Бележки за оптимизации (които директно свалят разхода)
- **LLM модел избор**: “mini/small” модели за повечето въпроси, “large” само при нужда
- **Съкращаване на контекста**: по-малко retrieved chunks и по-къси chunk-и ⇒ по-малко input tokens
- **Кеширане** (въпроси/резултати) ⇒ по-малко LLM calls
- **Embeddings**: re-embed само при нужда; batch ingest; избягване на дублирани документи
